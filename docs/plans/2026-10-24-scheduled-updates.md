# 定时新增论文更新实施计划

用户授权新增定时抓取、自动入库、更新源码和操作手册；频率已选每天北京时间09:00。沿用独立项目与原来的模型配置。使用 writing-plans 与测试驱动流程实施，不更改原 DocTrace。

设计：Windows 当前用户的计划任务运行项目 Python 协调器。只读取指定仓库 README 最新提交的前四会议，保留旧资料，发现新标题和新增可用链接；已索引论文不重新下载或向量化。每日最多下载/导入10篇，失败最多自动尝试3次，避免反复访问失效链接。未取得全文不当作可问答资料，旧目录90个不可用条目不默认整批重试。

应用仍用data/manifest.json与index_receipt.json作为公开基线；自动更新结果保存在忽略提交的data/.live_manifest.json与.live_index_receipt.json，优先读取。每日获取的上游commit与原目录快照保存在私有runtime/updates，不自动推送GitHub。旧问答及其证据保留。

增量构建：只在本项目全Docker app/lightrag可用时停两个服务，MySQL不停止。等待已有请求结束；复制本项目索引和逐论文回执至独立候选目录，固定SDK复用旧论文回执，仅导入新增全文。拒绝删除旧论文、改Embedding模型或改已有内容。核对片段数、旧片段内容与索引收据后切换；发布前有构建锁；任何失败保存日志并恢复旧索引与原服务。进程中断后下次运行依据事务日志恢复，不能把半成品当完成。

计划任务不保存账户密码或供应商密钥参数，只调用本项目脚本；不自动启动Docker Desktop。电脑关机、用户未登录或Docker不可用时无法保证09:00执行；支持错过后补执行、手动执行、禁用和删除。常规关闭Docker后记录跳过而不拉起全部服务。
