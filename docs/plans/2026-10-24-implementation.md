# 四大顶会区块链智能合约论文问答系统实施计划

用户已授权独立开发、复用模型配置、建立新数据库、发布 GitHub 并交付详细操作文档。采用新目录与独立 Git 仓库，不更改原 DocTrace。内部 Git 分支 codex/build；GitHub 路径 Top4Sec-SmartContract-RAG，中文项目名称保持用户指定文本。

架构：FastAPI + MySQL 8 + 独立 LightRAG + BGE-M3 / BGE Reranker / DeepSeek。界面提供中文问题、naive/mix、论文目录、会议/年份范围、逐条引用及 PDF 页码、登录和个人历史。以短事务保存 processing/completed/failed，账号级幂等；Cookie 名与旧项目不同。

隔离：Compose 项目 scpaper-rag；数据库 smartcontract_papers、账号 scpaper_app、MySQL 3308；LightRAG workspace smartcontract_top4_v1、9630；应用 8003。仅绑定本机。所有持久化和运行配置位于本项目 runtime/ 和 .env，不触碰原库、旧容器或旧模型文件。

语料：固定上游 commit aede99b97104f2f1dd447922d9b54902a89c81d9。SP 48、CCS 61、USENIX 62、NDSS 46，共217目录记录；166有原链接、51空链接。按论文标题去重。仅索引成功获得且通过基本全文解析检查的论文，空链接、非论文PDF、失效链接保留状态。PDF全文不作为公开仓库附件。

图谱：采用 LightRAG 支持的 custom KG，论文—会议—年份—页/文本片段的可验证关系，全文向量同样由既有 BGE-M3 生成。无需为全文逐段调用生成模型抽实体，避免成千上万次图谱抽取调用。图不是LLM语义实体抽取产物。custom KG 写入不具备上游标准文档路径的完整恢复日志，因此只在服务停止时建立独立构建目录，保存逐论文回执与内容哈希，通过检查后再启动只读查询服务；禁止在线并发重建同目录。
