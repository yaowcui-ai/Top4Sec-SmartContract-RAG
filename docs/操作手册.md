# 四大顶会区块链智能合约论文问答系统操作手册

本手册对应 2026 年 10 月 24 日建立的独立项目。日常使用只需要启动服务，不需要重新下载论文、重新生成向量或重新建库。系统使用自己的 Docker MySQL、LightRAG 存储和登录账户，不使用原 DocTrace 数据库。

## 一 先分清三个服务

| 服务 | 本机位置 | 用途 |
| --- | --- | --- |
| 用户网页和业务后端 | http://127.0.0.1:8003/ | 登录、选择论文、提问、查看引用和个人历史 |
| LightRAG 管理页面 | http://127.0.0.1:9630/webui/ | 查看新论文库的索引与图；日常提问不需要进入此页 |
| 新 MySQL | 127.0.0.1:3308 | 保存本项目的用户、会话、问答记录 |

新数据库名称固定为 `smartcontract_papers`，数据库账号是 `scpaper_app`。原 DocTrace 的数据库是另一个服务/端口；本项目没有导入、清空或覆盖原数据库。

本机项目目录：

```powershell
C:\Users\86139\Documents\ChatGPT\实习项目\smartcontract-paper-rag
```

后面的命令都在这个目录执行。打开 PowerShell 后先输入：

```powershell

```

系统支持两种启动方式：A 是“Docker 运行数据库和知识库，PowerShell 运行业务后端”；B 是“三个服务全部由 Docker 运行”。二选一，不要让两种方式同时占用 8003。

## 二 日常启动方式 A 使用 PowerShell 运行后端

### 1 打开 Docker Desktop

在开始菜单打开 Docker Desktop，等待引擎启动完成。再在 PowerShell 中检查：

```powershell
docker version
```

能看到 Server 信息才说明引擎可连接。若只有 Client，或者报 `dockerDesktopLinuxEngine` 管道不存在，先等待 Docker Desktop 就绪，不能据此判断项目代码失败。

### 2 进入项目目录并启动两个依赖服务

```powershell
Set-Location 'C:\Users\86139\Documents\ChatGPT\实习项目\smartcontract-paper-rag'
docker compose --profile full stop app
docker compose up -d mysql lightrag
docker compose ps
```

第一行停止可能由方式 B 启动的本项目 app 容器，为 PowerShell 后端腾出 8003；不会停止旧项目。接下来只启动本项目的 MySQL 和 LightRAG。容器状态出现 Up 不代表应用立即就绪，初始化通常还需要等待。

### 3 启动业务后端

在同一个 PowerShell 窗口运行：

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8003
```

看到启动完成后保持这个窗口运行。命令没有回到提示符属于正常情况，因为它正在提供网页和接口；关闭该窗口或按 Ctrl+C 都会使这个后端停止。

### 4 打开网页

浏览器打开：

```text
http://127.0.0.1:8003/
```

使用 `127.0.0.1`，不要在配置未改变时换成 `localhost`，因为浏览器来源校验要求与配置一致。第一次打开或网页修改后，可按 Ctrl+F5 强制刷新。

### 5 验证服务状态

保留运行后端的窗口，另开一个 PowerShell，执行：

```powershell
Set-Location 'C:\Users\86139\Documents\ChatGPT\实习项目\smartcontract-paper-rag'
.\.venv\Scripts\python.exe scripts/manage.py status
```

该命令只检查状态、目录和容器，不调用模型。`/health` 正常表示业务应用存活；不代表模型账户余额、网络和全部知识库内容都已验证。

## 三 日常启动方式 B 全部使用 Docker

### 1 先停止方式 A 的后端

如果之前在 PowerShell 启动过 uvicorn，回到那个窗口按 Ctrl+C。必须先释放 8003，才能让 app 容器使用同一个端口。

### 2 启动完整服务

```powershell
Set-Location 'C:\Users\86139\Documents\ChatGPT\实习项目\smartcontract-paper-rag'
docker compose --profile full up -d --build
docker compose --profile full ps
```

本命令启动 mysql、lightrag 和 app。`-d` 表示后台运行，执行结束后 PowerShell 可以关闭，服务仍会运行。第一次构建镜像可能要下载依赖；以后代码未变化时，可使用：

```powershell
docker compose --profile full up -d
```

### 3 打开相同网页

```text
http://127.0.0.1:8003/
```

查看后端日志：

```powershell
docker compose --profile full logs --tail 80 app
```

持续观察日志：

```powershell
docker compose --profile full logs -f --tail 80 app
```

对 `logs -f` 按 Ctrl+C 只结束日志观察，不会停止后台容器。

## 四 从 Docker Desktop 界面启动和停止

1. 打开 Docker Desktop，进入 Containers。
2. 找到名为 `scpaper-rag` 的项目组，确认没有点到 DocTrace 或其他项目。
3. 如果之前用全 Docker 方式创建过三个容器，可启动该项目组中的 mysql、lightrag、app。
4. 如果只需要方式 A，只启动 mysql 和 lightrag，app 由 PowerShell 命令启动。
5. 服务启动后访问 8003；管理知识库时访问 9630。
6. 停止时点击本项目组对应服务的 Stop。不要使用 Delete 或删除数据目录来代替停止。

如果 Docker Desktop 中还没有 app 容器，先运行一次方式 B 的 `docker compose --profile full up -d --build`，因为界面不能替你创建尚未构建的应用镜像。

## 五 登录账号与密码

默认用户名为 `researcher`。实际初始密码在本机私有 `.env` 的 `APP_ADMIN_PASSWORD` 中；它没有写进 GitHub 或本手册。可以在 VS Code 中打开项目 `.env` 查看。

`.env` 中的不同密码用途：

| 配置项 | 用途 |
| --- | --- |
| APP_ADMIN_PASSWORD | 本项目网页初始账号密码 |
| MYSQL_PASSWORD | scpaper_app 连接新 MySQL 的密码，不是网页密码 |
| MYSQL_ROOT_PASSWORD | 新 Docker MySQL 的管理员密码，不是原本机 root 密码 |
| LIGHTRAG_API_KEY | 保护本项目知识库服务，不是供应商密钥 |
| ANSWER_API_KEY / RERANK_API_KEY | 后端调用模型供应商的密钥，不能发到浏览器或 GitHub |

首次启动只在账号不存在时创建默认账号，不会每次启动重设密码。仅修改 `.env` 的 APP_ADMIN_PASSWORD 不会覆盖数据库里已存在的密码哈希。

如需新增网页账号，在方式 A 的环境下执行：

```powershell
.\.venv\Scripts\python.exe scripts/manage.py create-user --username reader
```

按提示输入并确认 8–64 位密码。输入时不显示字符是正常现象；不要把密码作为命令行参数写进去。

## 六 完整过一遍问答

1. 登录后查看顶部“全文已索引”的实际数量。
2. 在论文目录中按会议、年份或标题筛选，确认目标论文为“全文已索引”。“有目录记录”“下载成功”“解析成功”与“已索引”是不同状态。
3. 点击“针对这篇提问”，系统会把论文标题写入输入框；先检查问题再提交，不会因为点击按钮自动调用模型。
4. 初次可问：`SmartPulse 如何验证智能合约的时序性质？请说明方法与适用范围，并引用原文。`
5. 选择 naive（向量检索）或 mix（图与向量混合），点击提交。一次请求只运行所选模式，切换下拉框本身不会调用模型。
6. 等待期间不要重复提交。成功后问题与答案出现在同一条对话中。
7. 点击答案中的 `[1]` 等编号，展开该条回答的原文片段、论文标题、会议和 PDF 页码。
8. 点击“打开本机原始 PDF”，浏览器进入对应文件页。这里的页码是 PDF 文件从第一页开始计算的位置，不一定与论文印刷页码相同。
9. 点击左侧个人历史，可回到相应对话；刷新和读取历史不会重新调用模型。

会议与年份范围会约束可用证据。当前范围筛选发生在 LightRAG 召回之后；范围内未召回片段不等于该论文或整个知识库中没有答案。建议在具体问题里写清论文名称。

系统不把未取得全文的目录条目当成已读论文，也不根据图片、公式或未提供的实验数据编造结论。引用能帮助追溯来源，但仍需核对模型对原文的解释。

## 七 请求失败 重试和刷新

### 网络断开或页面没收到结果

可能只是浏览器没有收到结果，服务端仍在处理。先刷新个人历史，查看原记录状态，不要立即把相同问题当成新问题反复提交。

页面保留原操作编号后，可点击“重试原操作”；它携带原来的问题、模式和范围。若结果已保存，服务器复用原结果，避免再次调用模型。相同操作编号改问题或模式会被拒绝。

### 记录显示 failed

查看阶段和错误类型。retrieval 是知识库检索，generation 是回答模型，persistence 是数据库保存。模型超时不能被解释成“知识库没有答案”。

已经保存的失败请求不会自动重新执行。确实要重新调用时，先结束上一条操作跟踪，再主动提交新操作；新操作可能产生新的模型费用。

### 记录一直显示 processing

这只说明尚未保存最终状态，不能据此断定仍在运行。可能仍在处理，也可能进程曾被中断，或最终数据库写入失败。当前版本没有完整的跨进程任务恢复队列；需要结合日志和服务状态判断。

“结束跟踪”只清除本页的待确认操作，不取消后台请求、不删除数据库记录，也不恢复尚未持久化的答案。

## 九 重启和修改代码

只重启全 Docker 后端：

```powershell
docker compose --profile full restart app
```

修改 Python、HTML 或 JavaScript 后，全 Docker 方式需要重新构建应用镜像：

```powershell
docker compose --profile full up -d --build app
```

方式 A 则按 Ctrl+C 停止旧 uvicorn，再运行原启动命令。网页修改后按 Ctrl+F5。

修改模型密钥后也要重启相应服务。更换 Embedding 模型或生成方式不能直接沿用旧向量索引；不能只改维度后继续检索。

回答和重排客户端默认直接连接供应商，不自动继承桌面代理。本机曾出现代理对较大 POST 请求中断 TLS、而直连正常的情况。确实需要供应商走环境代理时，在 `.env` 设置 `PROVIDER_TRUST_ENV=true` 并重启后端；本地 LightRAG 请求始终绕过环境代理。Docker 内的 127.0.0.1 指向容器自身，不能直接填桌面代理的回环地址。

## 十 从 GitHub 首次部署到另一台电脑

下面是首次安装步骤，已经配置好的本机不用每天重做。

```powershell
git clone https://github.com/yaowcui-ai/Top4Sec-SmartContract-RAG.git
Set-Location Top4Sec-SmartContract-RAG
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.\.venv\Scripts\python.exe scripts/init_config.py
```

脚本生成全新的本项目账号和密码，不覆盖已有配置。自行填写 `.env` 和 `.lightrag.env` 中的供应商地址、模型与 API Key；模板不含实际凭据。

下载和解析论文：

```powershell
.\.venv\Scripts\python.exe -m app.corpus collect --workers 4 --resolve-missing
```

该步骤只访问公开论文与元数据，不进行模型向量化。失效链接、未提供全文和访问受限的来源会记录为不可用，不绕过付费或登录限制。

首次构建索引前，停止本项目的应用与 LightRAG，保留数据库服务即可：

```powershell
docker compose --profile full stop app lightrag
```

若有方式 A 的 uvicorn，也先按 Ctrl+C。然后执行：

```powershell
.\scripts\build-index.ps1
```

该脚本使用固定 LightRAG 镜像调用 SDK，把已经解析的论文页面切分为 1200 token、重叠100，再计算向量并写入论文结构图谱。首次向量化会调用供应商并产生费用；本机已经建好的库不需要重复执行。

完成后必须看到 `VERIFIED`，并确认 `data/index_receipt.json` 的 status 为 verified。构建锁存在时，应用不会将半成品当成可用知识库。单次写入失败可依据已有逐论文回执继续当前同一构建；语料或 Embedding 配置变化时不会自动覆盖已有构建。

公开的 index_receipt.json 是作者本机的历史验收记录，不代表新电脑已建好索引。应用还要求本机私有 `data/.local_index.json` 与构建编号匹配，并检查论文文件存在；这个本机标记不上传 GitHub。新克隆时，下载脚本会补取缺失的 PDF 和正文，不会因为历史清单写着 parsed 就跳过。

## 十一 知识库范围和图谱说明

来源为指定 GitHub 目录的固定版本，只处理前四个安全会议：IEEE S&P、ACM CCS、USENIX Security、NDSS。原目录有217条记录，标题去重后216篇。最终可问答全文数量以 `data/index_receipt.json` 为准；原始目录和逐篇状态分别保存在 `data/source`、`data/manifest.json`。

图谱由论文、会议、年份与页内全文片段的结构关系构成，并非对每个段落额外调用生成模型抽取实体关系。这样保留可核对的来源结构并减少建库调用；不能将它描述为完整的智能合约漏洞语义知识图谱。

LightRAG 的 custom KG 导入路径不具备标准文档路径的全部恢复日志，本项目使用离线构建锁、确定性身份和逐论文回执控制构建。不要通过管理页随意删除其中的共享节点或与离线构建同时改写同一索引。

PDF 原件和正文存放在本机 `data/pdfs`、`data/text`，没有作为论文附件重新发布到 GitHub。公开仓库提供程序、来源目录、状态和复现步骤；重新安装不能仅靠 GitHub 代码自动获得作者本机已建索引。

## 十二 查看新数据库和备份

如需用 MySQL Workbench 检查，创建一条新的 TCP 连接：Host 为127.0.0.1、Port为3308、User为scpaper_app、密码取本项目 `.env` 的 MYSQL_PASSWORD。不要选原来指向3306的连接来操作本项目。

可执行只读查询：

```sql
SELECT DATABASE();
SHOW TABLES FROM smartcontract_papers;
SELECT status, COUNT(*) FROM smartcontract_papers.paper_qa_records GROUP BY status;
```

备份问答数据库前先停止业务后端，MySQL 容器保持运行：

```powershell
.\.venv\Scripts\python.exe scripts/manage.py backup-db
```

备份使用 utf8mb4，并直接以原始字节写入 `backups/时间/smartcontract_papers.sql`，避免 PowerShell 重定向造成中文字符损失。备份含账号哈希、会话和个人问答，只在本地保留，不上传 GitHub。

要保留完整应用，还需在 LightRAG 停止后另行复制 `runtime/lightrag`、`data` 和私有配置。数据库备份不包含论文向量和图索引。已有备份不要覆盖，恢复前必须先验证目标项目与数据库，不能在原 DocTrace 库上试验。

## 十三 常见问题

| 现象 | 优先检查 |
| --- | --- |
| 8003打不开 | 后端是否运行、app容器是否正常、是否用了正确端口 |
| 地址已被占用 | 是否同时启动了PowerShell后端和app容器；只停止本项目冲突进程 |
| Docker管道不存在 | Docker Desktop引擎是否已就绪 |
| 网页能打开但不能登录 | 新MySQL容器、3308端口和本项目账号配置 |
| 来源不受信任403 | 是否用127.0.0.1:8003访问；AUTH_ALLOWED_ORIGIN是否一致 |
| 全文已索引数量为0 | 构建是否完成，构建锁是否仍存在，收据是否verified |
| 下载成功但暂不能问 | 解析与向量/图索引是不同阶段，以索引收据为准 |
| 生成阶段报错或超时 | 模型供应商状态、密钥、余额与网络；不是直接判定无答案 |
| 重排发生降级 | 已回退原顺序，结合原文核对，不把降级当正常优化结果 |
| 代理开启后本地检查异常 | 优先直接访问127.0.0.1；项目内部检索客户端不经过桌面代理 |
| 旧历史没有显示 | 是否登录了同一项目的同一账号；不要混用DocTrace和本项目端口 |

需要定位问题时，提供错误阶段、HTTP状态和记录编号即可，不要发送 `.env`、API Key、数据库密码或会话Cookie。
